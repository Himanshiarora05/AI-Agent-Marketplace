# Crawl & Render Audit Skill

## When to use
Use this skill to diagnose technical issues that prevent search engines and AI assistants from accessing, reading, and indexing website content. This covers crawlers blocking (robots.txt, HTTP blocks), Client-Side rendering barriers (JavaScript reliance), mobile responsiveness (viewport tags), missing structured data (JSON-LD, FAQPage schema), and text locked inside opaque media (images without alt, canvas).

## Inputs
* `url` (string): The full absolute URL of the website to audit (e.g. `https://example.com`).

## Procedure
1. Locate the packaged script [check_technical.py](scripts/check_technical.py).
2. Execute the script with the input URL and a destination path for the JSON output:
   ```bash
   python skills/crawl-render-audit/scripts/check_technical.py <url> --output technical_findings.json
   ```
3. Read the generated `technical_findings.json`.
4. Synthesize the findings into standard report items. For each detected issue:
   * Match the status of each check (`robots_txt`, `crawler_block`, `js_render_gap`, `structured_data`, `locked_content`, `viewport_check`, `faq_schema_check`).
   * If a check status is `fail` or `warning`, formulate a corresponding finding in the final JSON schema. If `js_render_gap` is `unavailable`, report the limitation in execution/scope metadata and do not treat tool unavailability as a site defect.
   * If Playwright is not present, `js_render_gap` will report status `unavailable` which maps to a warning severity `medium`. Do not ignore it.
   * Assign appropriate severity (`critical`, `high`, `medium`):
     * **Critical**: Complete blocking of all AI bots, confirmed HTTP access denial (for example 403/429), severe client-side rendering gaps (huge content delta between raw and rendered text), or JSON-LD formatting errors that break parsers.
     * **High**: Blocking specific AI bots, moderate JS-render dependencies, or complete absence of structured JSON-LD data on key landing/product pages.
     * **Medium**: Missing viewport metadata tags, missing sitemap declarations, partial JS-render warnings, high ratio of images lacking alt text, or question content on-page without corresponding FAQPage JSON-LD.
   * Provide the exact `evidence` generated by the script.
   * Generate a targeted, mechanism-sound `suggested_action` describing how to fix it.

## Output
An array of findings following the required schema. If no issues are found, return an empty list.

## Accuracy guardrails

- A missing canonical is informational, not automatically a defect.
- Redirect warnings require a long (3+) hop chain or a cross-host redirect.
- Schema recommendations are page-type aware; absence of a schema type that is not relevant to the page archetype is not a failure.
- Visible/JSON-LD fact parity normalizes phone formatting and currency/decimal formatting to reduce false positives.
- Potential orphan detection is explicitly limited to the sampled sitemap/internal-link graph and is never presented as proof that a page is globally orphaned.
- Crawling remains bounded, same-domain, read-only, and robots-aware.
